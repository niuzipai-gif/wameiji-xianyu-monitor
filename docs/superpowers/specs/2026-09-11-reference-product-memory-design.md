# 正样本参考产品记忆：设计规格

日期：2026-09-11
状态：用户已确认全部参考截图均为认可的正样本；价格不是固定训练标签；已授权对每个样本产品做受控的闲鱼/挖煤姬页面核验。

## 目标

把 `F:\竞品图存放处\参考选品` 的商品详情截图导入为可审计的本地参考产品记忆。新的挖煤姬/闲鱼候选必须能获得：

1. 与哪个参考产品一致或相似；
2. 依据是什么（条码、共享标题词、版本词或仅无证据）；
3. 一个只用于采集优先级的 `reference_score`；
4. 不依赖历史价格的结论。价格仍由现有详情优先的实时证据链单独验证。

## 输入与不变约束

- 输入目录的 125 张 PNG 都是正样本；没有负样本，不能把“未命中”解释为“不值得做”。
- 文件是闲鱼商品详情截图，包含商品标题、版本/特典、品相、封面，部分含 EAN/JAN 条码。
- 本机可用 Pillow、pyzbar 和 Tesseract。OCR 文本必须附带实际语言能力状态；条码可作为强证据，OCR 失败不能阻断导入。为读取本批中文/日文截图，允许使用已校验、仅本机加载的 Tesseract `eng`、`jpn`、`chi_sim` 语言数据；不把图片上传给 OCR 服务。
- 不调用外部视觉模型或付费 API、不下单、不发布、不修改账号状态。
- 已授权的真实页面核验仅用于补充商品身份、版本和带时间戳的市场观察：每次只打开当前产品在闲鱼和挖煤姬的检索/详情页，记录后立即关闭本任务页签；不处理验证码、不输入凭据、不绕过登录、付费墙或站点限制。
- 采购侧暂时无低价、无货或价格不合适只能记为 `price_unfavorable` / `not_currently_listed` 的市场状态，绝不是负样本、淘汰结论或产品身份的否定。
- 现有详情优先、登录预检、质量暂停、两边证据新鲜度和利润计算规则不得被放松。

## 方案

采用“证据优先的混合产品记忆”，而不是端到端视觉二分类：

```
认可截图
  -> 本地提取（SHA-256、EAN/JAN、可用 OCR、规范化词）
  -> reference_products / reference_product_samples
  -> 新候选的条码精确匹配或多词交集匹配
  -> reference_candidate_matches
  -> 独立的双市场观察（身份/版本/状态/时间；价格可波动）
  -> 采集/复核优先级和可读证据
  -> 现有实时价格、成本、利润评估
```

### 产品身份

- 有条码的样本按规范化 EAN/JAN 合并为同一个参考产品，条码精确命中得分 1.0。
- 没有条码的样本按文件内容 SHA-256 保持独立，绝不因为封面或一个模糊词就合并不同版本。
- 每个样本保留源文件绝对路径、校验和、提取文本、条码、词集合和 OCR 状态；重复导入必须幂等。

### 候选评分

- 输入来自已发现的候选字段：`title`、`artist`、`edition`、`catalog_no`、`jan`、`raw_text`。
- 任意规范化 EAN/JAN 一致为 `exact_barcode`，`reference_score=1.0`。
- 没有精确编号时，至少两个有信息量的共享词才可形成 `token_overlap`；得分由共享词覆盖度和交集比例组成，并记录共享词。单个 `CD`、`DVD`、`LP` 等通用词不能单独命中。
- 未达门槛返回 `no_match` 和 0 分，表示“现有正样本尚无证据”，不是负样本或屏蔽规则。
- `reference_score` 只提高详情/人工复核优先级，不覆盖媒体完整性、登录安全、两侧新鲜度或利润门槛。

### 持久化与接口

新增三张 SQLite 表：

| 表 | 用途 |
| --- | --- |
| `reference_products` | 稳定产品身份、条码、词集合和样本数量 |
| `reference_product_samples` | 每张截图的可审计特征和校验和 |
| `reference_candidate_matches` | 候选的当前最佳参考匹配、得分和证据 |
| `reference_market_observations` | 每个参考产品在闲鱼/挖煤姬的带时间戳观察；不产生静态价格标签 |

提供离线 CLI 导入命令、观察记录命令和只读 API：导入命令要求显式目录和数据库，API 只展示覆盖率、已训练样本、候选匹配和市场观察摘要，不接受任意服务器路径。浏览器不会由服务器或 CLI 自动启动；真实页面观察由受控人工/电脑操作批次记录。常规发现流程在写入候选后刷新其参考匹配；任何刷新错误以受控诊断返回，不能阻断原有详情证据流程。

## 验收标准

1. 可在临时 SQLite 中幂等导入模拟截图特征，并保留正样本来源/校验和。
2. JAN 精确命中、两个独特标题词命中、单一通用词和无匹配均有确定性测试。
3. 新候选写入发现流程后带有可读的参考匹配，未命中候选仍可进入原有详情队列。
4. CLI 对实际 125 张截图给出总数、导入数、已存在数、条码覆盖和 OCR 能力状态；导入本身不发起网络请求。
5. 每个导入样本产品可有闲鱼与挖煤姬的独立市场观察，观察包含时间、身份/版本证据和状态；页签观察完成后关闭，且无低价/无货不会降低 `reference_score`。
6. API 只读返回状态、候选证据和市场观察摘要；完整离线测试、格式检查通过。

## 非目标

- 不将价格、浏览量、收藏数或“已售”状态作为静态训练标签。
- 不在只有正样本的前提下声称具有全品类负样本分类能力。
- 不替代现有真实价格、成本、匹配完整性和人工复核。
- 不把一次网页观察、采购侧无货或当前价格，固化为长期市场结论。
