# 选品证据画像 V2：设计规格

日期：2026-09-11  
状态：用户确认先优化已导入的 125 个正样本参考记忆，再开展陌生品类泛化选品。

## 目标

在现有的“正样本参考产品记忆”之上，提供一个可解释的 V2 证据画像层。它应当让操作者看清：

1. 一个候选为何与哪个认可样本有关联；
2. 这项关联属于精确身份、版本/目录号，还是多词相似证据；
3. 闲鱼与挖煤姬的**最新**市场观察分别是什么；
4. 哪些字段没有证据、必须继续核验。

V2 的输出是详情核验和人工复核的优先级，不是“可售/不可售”的自动判决。

## 已确认的输入和不变约束

- `F:\竞品图存放处\参考选品` 的 125 张截图均为认可的正样本；不存在负样本。
- 所有样本已经以本地 SHA-256、可用 OCR、EAN/JAN、词集合以及带时间戳的双市场观察导入 SQLite。
- 某一时点的价格、高价、无低价货源、`not_currently_listed`、登录状态或一次网页检索失败，不得改变产品的正样本身份，也不得作为负标签或匹配分数输入。
- 必须保留现有详情优先、媒体完整性、登录安全、价格/成本/利润和人工复核关卡；参考证据不能越权。
- 不调用外部视觉模型、不发起付费请求、不下单、不写入站点账号；浏览器市场核验仍由受控、页签有界的人工/电脑操作完成。
- 工作区已有未提交的登录恢复改动不属于本规格范围。

## 方案比较

### 方案 A：证据画像 V2（采用）

从已保存的产品、截图和市场观察中生成确定性的身份画像与最新市场快照。候选继续使用“条码精确命中 / 至少两个非通用身份词命中”的高精度规则，画像只提升可读性和复核优先级。

优点是可审计、没有把临时供给误训成标签、适用于当前全正样本数据。缺点是不会假装拥有陌生品类的二分类能力。

### 方案 B：单类图像相似度

用 125 张截图建立封面相似度索引。它可辅助找视觉相近品，却很难可靠地区分同封面不同版本、特典完整性和原版/复刻；证据也不如条码与目录号可复核。因此不作为选品决策模型。

### 方案 C：正负二分类器

它适合后续拥有明确失败样本或经营结果后的泛化选品，但当前没有负例、目标利润结果或长期销量标签。现在训练会把缺货或高价错当作负例，违反已确认的约束。

## 架构与数据流

```text
认可截图 + 已记录的双市场观察
  -> reference_products / reference_product_samples / reference_market_observations
  -> 确定性证据画像（按产品生成，不猜测未知字段）
  -> 最新状态汇总（按产品、市场取 observed_at + id 最新的一条）
  -> 候选身份匹配（现有条码 / 多个非通用词规则）
  -> 详情与人工复核优先级
  -> 既有实时成本、完整性、利润、合规决策
```

### 证据画像

新增一个纯读取的 `build_reference_product_profile` 服务接口，而不是新建带主观标签的训练表。每个画像只包含可追溯来源的字段：

- 稳定产品键、EAN/JAN、已观察到的目录号；
- 经过去重后的非通用身份词；
- 来源截图数、OCR/条码提取状态；
- 每个市场的一条最新观察，以及其原始标题、版本证据、时间和来源链接；
- `unknown`/缺失字段的显式表示。

不从价格、库存、搜索结果页排序、收藏数或截图视觉风格推断产品品质。市场观察中的 `price` 只保留为带时间戳的事实，不进入画像匹配分数。

### 最新市场状态

现有状态接口会保留兼容的历史观察总数，但增加 `latest_market_coverage`：对闲鱼和挖煤姬分别返回已覆盖产品数、未覆盖产品数、按最新状态分组的数量和最新观察时间。历史 `login_required` 不能覆盖恢复登录后同一产品的 `found` 或 `not_currently_listed`。

市场画像查询按产品和市场使用 `observed_at DESC, id DESC` 选取唯一最新记录；同一时间戳下以较大的记录 ID 打破平局。

### 候选匹配与优先级

保留现有强度边界：

- 相同 EAN/JAN 为 `exact_barcode`，分数 `1.0`；
- 没有条码时，至少两个非通用身份词才可形成 `token_overlap`；
- 不足证据为 `no_match`，其含义仅是“正样本库尚无关联证据”；
- 画像接口返回匹配证据和最新市场快照，但不把市场状态加入 `reference_score`。

前端选品板和只读 API 显示“参考证据 / 当前市场观察 / 仍需确认的字段”三类信息。任何候选仍须通过既有实时详情、完整性和利润流程才可能进入后续选择。

## 接口与组件边界

| 组件 | 责任 | 不负责 |
| --- | --- | --- |
| `core/reference_memory.py` | 候选和参考产品的纯身份匹配 | 数据库、价格、浏览器、市场判断 |
| `services/reference_memory.py` | 从持久化证据生成画像和最新状态汇总 | 改变正样本标签、自动发现或账号操作 |
| SQLite 读取查询 | 按确定排序取最新观察并保留历史 | 删除或重写历史市场观察 |
| Web API / 选品板 | 只读展示画像、匹配和状态 | 导入任意路径、发起浏览器、修改账号 |
| 既有发现与详情流程 | 写入候选后刷新身份匹配 | 用参考分数跳过完整性、成本或利润门槛 |

## 错误处理

- OCR 缺失、条码缺失或市场没有观察时，画像返回已知部分与明确的缺失状态，不阻塞候选进入既有详情队列。
- 损坏的 JSON 或无法解析的持久化身份字段遵循现有受控诊断策略；可选画像错误不能中断发现流程。
- 空数据库、只有一个市场、只有历史观察和同时间戳观察都必须返回确定结果。
- URL 和文本继续采用现有敏感参数清理与长度校验；不将凭据写进画像或 API。

## 验收与测试

1. 给同一产品依次写入历史 `login_required` 和后续 `found`，V2 最新汇总只统计后者，历史总数仍可审计。
2. 有观察和无观察的产品画像均能稳定返回；时间相同时按观察 ID 选择最新记录。
3. 条码精确匹配、多词匹配、通用词单独出现和未匹配的现有行为不变；价格与市场状态改变不能改变 `reference_score`。
4. 新 API 只读、无外部网络请求；限额、空库、错误参数和历史兼容字段有测试。
5. 选品板能同时区分“参考身份证据”“当前市场观察”“待核验信息”，且不显示任何由缺货/高价推导出的负向结论。
6. 全部参考记忆核心、存储、市场观察、发现和接口测试通过；手动读取本机 API 验证 125 个样本、双市场覆盖和最新状态数量。

## 范围外与下一阶段

本次不训练黑盒视觉模型、不创建正负二分类器、不把市场价格固化成标签，也不凭这 125 个正样本声称能预测任意陌生品类的利润。

V2 验收后，下一阶段才建立陌生候选的泛化反馈集：候选首先经画像获得可解释的复核优先级，随后由已验证的身份、完整性、成本、利润和人工反馈形成独立结果标签。那一阶段需要单独设计其标签定义、样本抽样、验证集和上线门槛。
