# 参考品类方向证据：设计规格

日期：2026-09-12  
状态：按用户已授权的“持续推进、由系统选择安全路径”执行。

## 目标

将 `F:\竞品图存放处\参考选品` 中 125 个已认可正样本转为一组可解释的**产品方向证据**。它回答的是：陌生候选的结构化产品身份是否落在已认可样本出现过的方向中，从而优先安排深入核验。

它不回答“这个品好不好”“是否应该采购”“当前价格是否划算”，更不得把未匹配、无货、高价、登录状态或一次搜索失败变成负面结论。

## 已知输入与约束

- 125 张参考图都是用户确认的好品正样本；没有对应负样本或经营结果标签。
- 当前已有候选身份匹配：条码精确命中或至少两个非通用身份词。它只表达同款/同身份关联。
- 已清除详情页店铺文案和 OCR 碎片导致的假身份匹配；119 个当前候选均为 `no_match`，这只表示没有同款身份证据。
- 市场观察、价格、库存、成本、利润和闲鱼/挖煤姬登录状态不得参与方向证据，也不得被此功能写入或改变。
- 功能只能本地读取 SQLite；不发起浏览器、网络请求、采购、消息或自动拒绝。

## 方案比较

### A. 确定性方向证据（采用）

从每个参考截图的 OCR 文字中识别少量、可审计的产品方向：实体音乐、主机游戏、画集/设定集/书籍、同人/动画作品、初回/限定/特典。对候选仅使用标题、艺术家、版别、型番、JAN 等结构化身份字段提取同一组方向。

优点：可解释、无额外付费或联网、不把暂时供货条件误训成负例。局限：只能提供“正样本覆盖”提示，不能预测利润或判断陌生产品必然适合。

### B. 图像嵌入或视觉相似度

可以比较封面风格，但当前样本主要是包含 UI、商品状态与文字的截图；也难以辨别同封面不同版本、特典和完整性。作为主决策不可靠，本期不采用。

### C. 直接训练好/坏二分类器

当前全是正样本，缺少明确负样本、长期销量和经营结果。训练会把“未匹配”“无货”或“价格高”误当坏品，违反约束。本期不采用；后续只在足量人工 `not_fit` 和经营结果标签后单独设计。

## 架构

```text
参考截图 OCR（每产品的已知文字）
  -> 纯规则方向提取（仅产品文本）
  -> 每个方向的已认可产品数 / 样本总数
  -> 本地只读方向概览 API
  -> 选品板显示“正样本覆盖，需继续核验”

候选结构化身份字段
  -> 同一纯规则方向提取
  -> 候选方向证据 API
  -> 详情和人工复核优先级（不改经营决策）
```

### 纯规则模块

新增 `core/reference_directions.py`。输入是文本或结构化候选字段，输出稳定的方向键；模块不依赖 SQLite、网络、价格或浏览器。规则采用中日英产品字段中明确可见的词组，不用易被闲鱼页面壳污染的泛化词（例如 `角色`）。

方向键固定为：

| key | 显示名 | 典型证据 |
| --- | --- | --- |
| `physical_music` | 实体音乐 | CD、专辑、音楽、album |
| `console_game` | 主机游戏 | Switch、PS Vita、ゲーム、Nintendo |
| `art_or_book` | 画集/设定集/书籍 | 画集、設定集、设定集、小说、小説、book |
| `doujin_or_anime` | 同人/动画作品 | 同人、アニメ |
| `limited_or_first_edition` | 初回/限定/特典 | 初回、限定、限定版、特典、limited |

多个方向可以同时成立；没有命中时返回空集合，而不是“不符合”。候选仅在结构化身份字段全空时才使用 `raw_text` 回退，以避免商店规则/物流文案制造方向。

### 本地读取服务与 API

服务从 `reference_products` 与 `reference_product_samples` 读取每个产品的 OCR 文本并去重产品 ID，返回：总认可产品数、每个方向的产品数和占比、来源固定为 `approved_reference_samples`、`network_requests: 0`。

候选方向查询从 `discovery_candidates` 读取结构化字段，返回候选 ID、命中方向及每个方向在正样本库中的覆盖数。未命中返回 `state: "no_direction_evidence"`；命中返回 `state: "positive_direction_covered"`。两种结果都显式返回 `decision_effect: "none"`。

两个端点均为 GET、本地只读：

- `/api/reference-memory/directions`
- `/api/reference-memory/candidate-directions?limit=200`

参数限额和错误格式遵循现有参考记忆 API。

### 选品板

参考正样本库面板显示前几个方向及“认可样本覆盖 N/总数”。候选/机会卡片若有对应候选 ID，则显示方向标签和说明“正样本方向证据，仍需详情核验”；若无方向证据不显示负向措辞。

前端只请求上面的本地 GET 端点；不显示市场价格、供给状态，不改变机会排序、利润、采购操作或人工反馈按钮。

## 错误与边界

- 空参考库返回总数 0 和空方向列表；不会出错或触网。
- OCR 缺失、候选字段为空或 JSON/数据库异常都显示“暂无方向证据/暂不可用”，不改变候选。
- 方向统计按唯一参考产品计数，不因同一产品多张截图增加权重。
- 规则输出和 API 数据中不包含商品价格、库存、市场状态、cookies 或账号信息。

## 验收标准

1. 纯规则测试验证中日英方向文本、复合方向、无关文本及结构化字段优先于详情原文。
2. 服务测试验证按唯一产品统计、空库、候选 `positive_direction_covered` / `no_direction_evidence` 和 `decision_effect: none`。
3. API 测试验证两个端点只读、无网络、限额及错误处理。
4. 静态选品板测试验证展示用语不含购买、拒绝、淘汰、价格或市场状态，并在方向 API 不可用时降级。
5. 现有条码/词匹配、市场观察、候选状态、采购价、机会决策和人工反馈不被修改。
6. 运行参考记忆相关测试、页面语法检查和全量 `pytest -q`。

## 后续阶段

当收集到足量、明确且可复核的人工方向反馈及经营结果后，单独定义训练集、保留集、误判成本和上线门槛；本设计不把当前方向覆盖伪装成二分类模型。
