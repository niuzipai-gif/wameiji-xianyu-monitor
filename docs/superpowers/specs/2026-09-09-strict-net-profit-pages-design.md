# WAMEIJI-XIANYU 严格净利机会流与公网快照设计

**日期：** 2026-09-09

**状态：** 用户已确认设计，待书面规格复核

**适用范围：** 双边最低价比较、净利润硬门槛、GitHub Pages 持久化展示，以及后续分阶段采集的停止条件

## 1. 目标

把选品广场恢复为可审计的双边机会流：左侧显示闲鱼国内最低有效售价（CNY），中间显示完整成本、净利润和匹配依据，右侧显示挖煤姬最低可购价（JPY 与折合 CNY）。只有同一版本、成本完整、两侧证据有效且净利率不低于 25% 的商品可以进入主信息流。

GitHub Pages 必须在没有本地服务、电脑重启、浏览器留有旧 API 配置的情况下，仍能显示最近一次发布的已验证快照及两侧图片。实时 API 只能由显式参数开启。

## 2. 不在本次范围内

- 不恢复或启动当前已暂停的采集任务。
- 不通过放宽 JAN、目录号、版本、成色或完整度条件来填充卡片。
- 不把成本缺失、负利润或净利率不足 25% 的记录伪装成机会。
- 不在净利润中加入尚无真实历史依据的固定售后准备金或风险准备金。
- 不把 GitHub Pages 变成持续连接本地电脑的实时控制台。

## 3. 已锁定业务口径

### 3.1 交易方向

唯一允许的利润方向是：

`挖煤姬日本采购（JPY） -> 运回国内 -> 闲鱼销售（CNY）`

闲鱼是销售侧，挖煤姬是进货侧。反向价差不能形成机会。

### 3.2 用户确认的固定成本

- 日本至中国头程：15 CNY/件。
- 中国境内包邮：5 CNY/件。
- 税费：按用户当前免税运输口径记 0 CNY，但必须作为显式配置保留，不能从模型中删除。
- 净利率口径：`净利润 / 闲鱼最低有效售价`。
- 主信息流门槛：净利润大于 0 且净利率大于等于 25%。

### 3.3 保守默认值

- 包装耗材：2 CNY/件。
- 闲鱼卖方服务费：默认按成交额的 1.6% 计算，不默认套用 60 CNY 封顶；账号类型明确后允许通过配置切换到适用费率和封顶规则。
- 汇率不用外部中间价代替，读取挖煤姬同一次详情快照中展示的结算汇率。当前已保存页面均显示 `1 JPY ≈ 0.0455 CNY`，但该数值不能永久硬编码。
- 挖煤姬代购手续费读取详情页。当前已保存的 57 份详情页面均显示 200 JPY，但该数值同样不能永久硬编码。

## 4. 成本和利润公式

对每一个严格匹配后的双边商品，使用以下字段：

- `xianyu_sale_cny`：闲鱼最低有效售价。
- `xianyu_seller_fee_cny`：按当前卖方费率政策计算的服务费。
- `wameiji_item_jpy`：挖煤姬商品价。
- `wameiji_domestic_shipping_jpy`：详情页实际日本境内运费。只有页面明确写明卖家承担时才能记为 0；金额未知时不得猜测。
- `wameiji_proxy_fee_jpy`：详情页实际代购手续费。
- `wameiji_fx_cny_per_jpy`：同一详情快照中的挖煤姬结算汇率。
- `international_shipping_cny = 15`。
- `china_postage_cny = 5`。
- `packaging_cny = 2`。
- `tax_cny = 0`，保留为可配置字段。

计算方式：

```text
wameiji_purchase_cny =
    (wameiji_item_jpy
     + wameiji_domestic_shipping_jpy
     + wameiji_proxy_fee_jpy)
    * wameiji_fx_cny_per_jpy

landed_cost_cny =
    wameiji_purchase_cny
    + international_shipping_cny
    + china_postage_cny
    + packaging_cny
    + tax_cny

net_profit_cny =
    xianyu_sale_cny
    - xianyu_seller_fee_cny
    - landed_cost_cny

net_margin = net_profit_cny / xianyu_sale_cny
```

金额按分展示；筛选必须在未提前四舍五入的数值上完成，避免 24.995% 被误判为 25%。

## 5. 证据与准入规则

一张主信息流卡必须同时满足以下条件：

1. 挖煤姬和闲鱼商品均为当前快照中可购买或在售的详情记录。
2. 优先用 JAN 或目录号匹配；缺少这些标识时，只允许现有严格标题、版本、艺术家和图片证据共同通过，不能用最高分兜底。
3. 版本、介质、特典、套装完整度、成色分组相容。低价配件、求购、空盒、损坏品或价格占位记录不能成为闲鱼最低价。
4. 闲鱼取同一商品中最低的有效在售价格，而不是平均价或最高价。
5. 挖煤姬取同一商品中最低的有效可购价格，并同时保留其详情页费用证据。
6. 所有公式字段均有来源；缺一项即为 `cost_pending`，不得进入机会流。
7. 两侧图片均已转存为可由 GitHub Pages 读取的相对资源，且发布前通过 HTTP 200 和非空文件校验。
8. `net_profit_cny > 0` 且 `net_margin >= 0.25`。

快照时间和两侧详情链接必须随卡片发布。历史卡不会因为电脑重启而消失，但用户下单前仍需重新核验价格和库存。

## 6. 系统边界

### 6.1 详情费用提取器

从保存的挖煤姬详情 HTML 中独立提取商品价、日本境内运费、代购手续费、站内汇率、库存和图片。明确的“卖家承担”转换为数值 0；“买家承担”但无金额保持未知。提取器只产出证据字段，不负责利润判断。

### 6.2 严格利润计算器

接收已匹配的双边详情和版本化成本政策，返回：完整成本拆分、净利润、净利率、状态及缺失字段。状态至少包括：

- `eligible`：证据完整且净利率达到 25%。
- `below_margin`：证据完整但净利率不足。
- `cost_pending`：存在未知成本。
- `match_rejected`：商品身份、版本或成色不相容。

每次计算保存成本政策快照，后续费率或汇率变化不能静默改写历史结果。

### 6.3 机会流投影器

API 与 Pages 导出使用同一筛选函数，只向主信息流返回 `eligible`。其他状态仅聚合为漏斗计数和原因，不生成商品卡，从源头避免本地与公网口径分叉。

### 6.4 Pages 快照导出器

从持久化 SQLite 读取符合条件的卡片、漏斗统计、策略版本和采集时间，输出：

- 版本化 JSON 快照。
- 快照 manifest 与内容哈希。
- 两侧本地图片资源。
- 数据更新时间、策略版本和来源状态。

导出必须是原子操作：全部 JSON 和图片验证成功后再替换当前公开快照。失败时保留上一份可用快照。

### 6.5 公网数据加载器

GitHub Pages 默认始终加载仓库内的已验证快照。浏览器 `localStorage` 中残留的 API 地址或 token 不得触发实时加载，也不得用空的远端结果覆盖快照。

只有 URL 显式包含 `?live=1` 时才尝试实时 API；实时 API 不可达或返回无效结构时，回退到公开快照并显示“实时连接失败，当前为最近快照”。

## 7. 前端表现

- 维持横向三栏卡片：左闲鱼、中利润、右挖煤姬。
- 左侧货币固定为 CNY。
- 右侧固定显示 `JPY（约 X CNY）`。
- 中间显示成本合计、净利润、净利率、匹配依据和成本展开项。
- 主信息流只出现达标机会；页面始终显示明确漏斗，例如当前基线“已核验 50 / 成本待核验 8 / 利润不足 38 / 达标 4”。如果达标数为 0，则保留漏斗和明确的零结果说明，不显示空白区域，也不用旧样本补位。
- 两侧图片都必须显示；单侧图片缺失时不发布该卡，并在发布诊断中计数。
- 显示快照生成时间和“下单前需重新核验”的提示，避免把历史快照描述成实时库存。

## 8. 已有数据的预期重算结果

以当前 50 组已保存双边记录作设计校验，按以下口径暂算：

- 页面汇率 0.0455 CNY/JPY。
- 页面代购手续费 200 JPY。
- 已解析的实际日本境内运费。
- 头程 15 CNY、国内包邮 5 CNY、包装 2 CNY、税费 0。
- 闲鱼费率 1.6%。
- A 口径净利率至少 25%。

预期漏斗是：4 组 `eligible`、8 组 `cost_pending`、38 组 `below_margin`。该数字是当前数据的回算基线，不是未来采集必须凑出的配额；正式实现必须由统一计算器重新生成并逐卡验证。

## 9. 后续采集恢复方案

本规格确认和实现均不等于恢复采集。只有用户后续明确要求恢复，才按以下阶段运行：

1. **干跑检查：** 验证登录态、持久化数据库路径、详情解析器、图片目录和停止开关，不访问商品页。
2. **10 条试跑：** 只抓 10 个挖煤姬候选并完成详情费用提取，再对严格标识执行低频闲鱼查询。
3. **50 条小批量：** 只有试跑正常才扩展；每个阶段展示候选数、详情有效数、闲鱼匹配数、成本完整数和最终达标数。
4. **扩量：** 小批量通过后才能继续。任何批次都不得为增加卡片而放宽匹配。

立即停止条件：

- 任一平台要求人工验证、登录失效或出现反爬限制。
- 详情解析成功率低于 80%。
- 图片成功率低于 90%。
- 数据货币或交易方向异常。
- 单批出现重复循环、计数不再增长或错误连续出现。
- 连续三个有完整阶段统计的批次均为 0 个达标机会。

停止后必须保留上一份公开快照，记录准确的阶段计数和停止原因，修正采集设计后重新从 10 条试跑开始。

## 10. 错误处理

- 成本缺失：记录字段名，归入 `cost_pending`，不展示卡片。
- 匹配冲突：归入 `match_rejected`，不得选第二高分兜底。
- Pages 快照损坏：拒绝替换，继续服务上一份快照。
- 图片下载或路径错误：拒绝发布对应卡片并记录失败数。
- 实时 API 空数据：在 `?live=1` 下显示失败并回退快照；默认 Pages 模式不访问实时 API。
- 数据库或导出失败：不清空当前公开数据，不启动采集补救。

## 11. 测试与验收

### 11.1 单元测试

- 完整公式覆盖每一项成本。
- 25% 精确边界通过，低于边界的最小差值失败。
- CNY/JPY 方向颠倒时拒绝计算。
- “卖家承担”解析为 0；“买家承担”无金额解析为未知。
- 任何成本字段缺失都返回 `cost_pending`。
- `below_margin` 与 `cost_pending` 永远不进入主信息流。

### 11.2 集成测试

- API 和 Pages 导出对同一数据库返回相同的合格 ID 集合与漏斗计数。
- 浏览器预置旧 API 地址和 token 后，普通 Pages URL 仍读取静态快照。
- `?live=1` 才访问实时 API，失败后正确回退。
- 快照发布中途失败时，上一份 manifest、JSON 和图片保持完整。

### 11.3 浏览器验收

- 用全新浏览器会话和带旧 `localStorage` 的会话分别打开 GitHub Pages。
- 两种普通打开方式都看到同一批合格卡和相同计数。
- 每张卡两侧图片均加载成功，无断图。
- 左侧显示 CNY，右侧显示 JPY 与折合 CNY，中间只显示挖煤姬进货到闲鱼销售的利润。
- 页面刷新、电脑重启或本地 9890 服务关闭后，公开快照仍可用。

### 11.4 运行安全验收

- Discovery Worker 计划任务保持禁用。
- 没有采集进程残留。
- 本次部署只读取现有数据库、重算、导出和发布，不访问新的闲鱼或挖煤姬商品页。
