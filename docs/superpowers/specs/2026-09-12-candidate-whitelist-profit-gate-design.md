# 候选白名单与利润门槛设计

## 已确认规则

`F:\竞品图存放处\参考选品` 导入并匹配到的候选，都是用户认可的可选品。
它们不再需要被系统判断是否“符合方向”。暂时无货、暂时没有低价、缺少一侧
报价或价格过期，都不得使候选降级或从池中消失。

商业结论只有两种：利润证据尚未齐全，或在同款、同版本、同品相的两侧新鲜
价格和成本齐全后，确认为有利润。购买、下单、消息和上架仍不自动执行。

## 数据与展示

`/api/discovery/board` 的候选列表改名为 `selectable_candidates`，并返回所有
活跃的白名单候选。每张卡保留身份、来源链接和证据新鲜度，新增只读的
`profit_readiness`：

- `profit_ready`：同款两侧价格与成本齐全，展示为可核利机会；
- `source_price_needed`：等待进货侧详情/价格；
- `resale_price_needed`：等待闲鱼销侧价格；
- `refresh_needed`：已有证据过期，等待复核。

没有任何状态代表“不符合”或“淘汰”。页面先显示已确认有利润的机会，再显示
所有可选品池，后者按利润证据接近程度排序，并明确说明“暂缺价格不降级”。

## 保护与兼容

- 价格、利润和可做结论仍只来自同款、同版本、同品相且新鲜的实际观察；参考图
  本身不被当作价格或利润证据。
- 旧 `research_candidates` 响应字段保留为 `selectable_candidates` 的兼容别名，
  以免现有本机页面在升级过程中变空。
- 不修改采集频率、登录流程、来源链接打开方式或任何交易动作。

## 验收

1. 所有活跃候选都出现在可选品池，即使未找到进货价或闲鱼价。
2. 候选卡和接口不含“不符合”“淘汰”或“无货即降级”的逻辑。
3. 只有新鲜、同款的利润证据才可标记为有利润可做。
4. 旧页面仍能读取候选数据；页面静态契约和 API 回归测试通过。
