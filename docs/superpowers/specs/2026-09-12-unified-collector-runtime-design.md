# 统一选品采集运行链路设计

## 目标

让本机采集、Render 副本、GitHub Pages 选品广场和本机调试看板都围绕
`data/local/dual-market.db` 这一份事实源运行。修复后，远程页面下达的命令由
Render 队列交给本机采集器；本机调试页面下达的命令也不会停留在未被消费的状态。

## 已确认的问题

当前正在运行的浏览器采集器写入 `dual-market.db`，本机 9891 看板也读取该库；
但副本发布器的默认值仍是 `takeover.db`。因此 Render 与 GitHub Pages 显示的是旧
库的状态，无法反映当前采集。采集器只轮询 Render 命令队列，本机看板写入本地
命令表的命令则没有消费者。

## 方案选择

1. 只手工为当前进程传入正确数据库：能临时恢复，但双击启动器或登录后自启动会
   再次回到旧库，拒绝采用。
2. 统一各启动器默认值并让总启动器显式传递同一数据库；采集器同时消费本地调试
   命令和 Render 命令：保留既有 GitHub Pages -> Render -> 本机采集器正式架构，
   也使本机调试页可用，采用。
3. 改为让本机页面把命令转发到 Render：需要给本地页面额外持有远程访问配置，
   增加耦合且不解决默认数据库分叉，拒绝采用。

## 运行规则

- `start-local.ps1`、`start-replica.ps1`、`start-discovery.ps1` 的默认数据库均为
  `data/local/dual-market.db`。
- `start-all.ps1` 接受一个数据库参数，并把同一个绝对路径显式传给本地 API、发布器
  和采集器；自动启动任务沿用这些正确默认值。
- `DiscoveryWorker` 每轮先读取本地命令表中的待执行本地命令，再拉取 Render 命令。
  Render 命令继续按其稳定远程身份镜像到本地，完成时同时回执 Render 和本地镜像。
  本地命令只在本地完成，不会被误回执成远程命令。
- 保留严格低频采集、登录预检、详情核验和“无机会不造假”的选择门槛；本改动不
  新增商品交易、卖家联系、购买或绕过登录/验证码。

## 验证

1. 启动脚本契约测试证明所有自动入口使用 `dual-market.db`，且总启动器显式传递它。
2. worker 测试证明一条本地 `scan_now` 命令会执行一次并在本地完成；现有远程命令
   回执测试继续通过。
3. 重启已确认的本地发布器和采集器后，核验 Render 摘要与本机 `dual-market.db`
   的候选/详情阶段一致；再从 Render 提交一条受控扫描命令，确认状态完成。

## 范围外

- 不推送 GitHub、不修改 GitHub Pages 仓库变量、不购买服务。
- 不修改用户正在编辑的闲鱼登录预检逻辑；只改其未触碰的默认数据库参数。
